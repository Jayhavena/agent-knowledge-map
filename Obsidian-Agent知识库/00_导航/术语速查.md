# 术语速查

| 中文名 | 英文 / 别名 | 坐标 | 一句话 |
|---|---|---|---|
| [[小模型·端侧模型]] | Small Language Model / On-device | `L0.P2` | 参数量小、可本地部署的模型，用于延迟敏感、隐私敏感或高频廉价任务。 |
| [[蒸馏]] | Distillation | `L0.P2` | 用大模型生成的轨迹或概率分布训练小模型，把能力压缩进更便宜的学生模型。 |
| [[基础大模型]] | Foundation Model / LLM | `L0.P2` | 通过大规模预训练获得通用语言理解与生成能力的模型，是 Agent 唯一的「思考引擎」。 |
| [[多模态输入]] | Multimodal Input | `L0.P2` | 模型直接读取图像、PDF、音频，跳过「先 OCR 再解析」的传统管线。 |
| [[模型路由]] | Model Routing | `L0.P2` | 按请求的难易程度，把流量分给不同价位、不同能力的模型；简单的走便宜的，难的不凑合。 |
| [[长上下文]] | Long Context | `L0.P2` | 单次可容纳十万至百万 token 的上下文窗口，把「先检索再喂」换成「全部塞进去」。 |
| [[推理模型]] | Reasoning Model / Extended Thinking | `L0.P3` | 在给出答案前先生成显式长链思考的模型，把「想多久」变成可调参数。 |
| [[测试时计算扩展]] | Test-time Compute Scaling | `L0.P3` | 在推理阶段投入更多采样、搜索或验证算力，用时间换准确率。 |
| [[原生工具调用]] | Native Tool / Function Calling | `L0.P4` | 模型直接输出结构化调用指令，而非在自由文本里夹带「我想调用某函数」的意图。 |
| [[提示注入]] | Prompt Injection | `L1.P1` | 攻击者把指令藏进模型会读到的任何文本（网页、文档、工具返回、文件名），诱导其改变行为。 |
| [[大海捞针测试]] | Needle in a Haystack | `L1.P2` | 在超长文本的随机位置埋入一个事实，考察模型能否准确取出。 |
| [[提示词自动优化]] | Automatic Prompt Optimization | `L1.P2` | 用评测信号驱动搜索或梯度式改写提示词，替代人工试错。 |
| [[上下文工程]] | Context Engineering | `L1.P2` | 系统性决定「每次调用时模型眼前摆什么 token」的工程实践，涵盖选取、排序、压缩、格式化与缓存。 |
| [[分块]] | Chunking | `L1.P2` | 把长文档切成一段段可检索的小块，切多大、从哪切，直接决定检索能不能命中。 |
| [[向量嵌入]] | Embedding | `L1.P2` | 把文本映射到高维向量，用余弦相似度衡量语义接近程度。 |
| [[少样本示例]] | Few-shot Examples | `L1.P2` | 在提示中给出若干输入输出样例，用模式匹配替代显式规则描述。 |
| [[指令层级]] | Instruction Hierarchy | `L1.P2` | 明确定义系统指令、开发者指令、用户指令、工具返回内容之间的优先级与冲突裁决规则。 |
| [[提示词模板]] | Prompt Template | `L1.P2` | 带占位符的提示词字符串，将任务说明与运行时变量拼装成最终输入。 |
| [[检索增强生成]] | Retrieval-Augmented Generation | `L1.P2` | 先从外部知识库检索相关片段，再连同问题一起送入模型生成答案。 |
| [[系统提示]] | System Prompt | `L1.P2` | 整段对话最前面、优先级最高的那段指令：你是谁、能做什么、不能做什么。 |
| [[重排序]] | Rerank | `L1.P2` | 对初筛出的一批候选做逐对精算相关性，再取 Top-K 送入模型。 |
| [[Agent 技能]] | Agent Skills | `L1.P2` | 把一套完整做法（说明 + 脚本 + 模板）打包成可按需加载的能力包，平时只占一行摘要。 |
| [[上下文压缩]] | Context Compression | `L1.P2` | 在长会话或多轮工具调用中，把历史压缩成摘要或摘要+关键原文，控制 token 增长。 |
| [[上下文腐化]] | Context Rot | `L1.P2` | 上下文越长，模型对其中任意一条信息的利用率越低，且错误更倾向于「看起来合理」。 |
| [[中间遗忘]] | Lost in the Middle | `L1.P2` | 模型对长上下文首尾两端的召回显著优于中段，呈 U 形曲线。 |
| [[代理式检索]] | Agentic RAG / Self-RAG | `L1.P2` | 让 Agent 自己决定检索什么、检索几次、结果够不够，不够就改写再查。 |
| [[图谱增强检索]] | GraphRAG | `L1.P2` | 把文档转成实体-关系图，用图的连通性与社区摘要回答「跨文档、多跳」问题。 |
| [[提示缓存]] | Prompt Caching | `L1.P2` | 把稳定前缀（系统提示、工具清单、长文档）的计算结果缓存，后续请求直接复用。 |
| [[提示词版本管理]] | Prompt Versioning | `L1.P2` | 把提示词当作代码：纳入版本控制、可评审、可回滚、每次变更跑回归评测。 |
| [[查询改写]] | Query Rewrite / HyDE | `L1.P2` | 在检索前用模型改写、扩展或假设性作答用户问题，缩小「问法」与「文档写法」的语义鸿沟。 |
| [[混合检索]] | Hybrid Retrieval | `L1.P2` | 同时做关键词（稀疏）与语义（稠密）检索，再融合两路结果。 |
| [[上下文压缩重写]] | Compaction | `L1.P6` | 接近窗口上限时，把整段历史重写成更短的摘要，再用它继续任务。 |
| [[引用锚定]] | Citation / Grounding | `L1.P7` | 要求每个事实性陈述都绑定到检索来源的具体片段，无来源则拒答或标注不确定。 |
| [[结构化输出]] | Structured Output | `L1.P7` | 强制模型只输出符合约定格式的 JSON 等结构，程序可以直接解析，不用从文本里抠。 |
| [[程序记忆]] | Procedural Memory | `L2.P2` | 把成功的操作序列沉淀为可复用的「怎么做」，下次直接调用而不重新探索。 |
| [[向量库]] | Vector Store | `L2.P2` | 专门用来存「语义向量」并快速找出最相似几条的数据库，RAG 和记忆系统都靠它做召回。 |
| [[工作记忆]] | Working Memory | `L2.P2` | 当前会话内可见的上下文窗口，承载本轮任务的临时状态。 |
| [[长期记忆]] | Long-term Memory | `L2.P2` | 跨会话持久保存的事实、偏好与经历，在需要时被召回进上下文。 |
| [[情景记忆]] | Episodic Memory | `L2.P2` | 按「时间 + 事件」组织的历史经历：某次发生了什么、结果如何。 |
| [[用户画像]] | User Profile | `L2.P2` | 结构化的用户属性集合：角色、水平、偏好、历史目标。 |
| [[知识图谱]] | Knowledge Graph | `L2.P2` | 以实体为节点、关系为边的结构化知识表示，支持多跳查询与逻辑约束。 |
| [[记忆与 RAG 的边界]] | Memory vs. RAG | `L2.P2` | RAG 是只读的、面向公共知识的检索；记忆是读写双向的、面向个体经历的状态。 |
| [[语义记忆]] | Semantic Memory | `L2.P2` | 与时间无关的稳定事实：用户偏好、组织架构、领域概念。 |
| [[记忆冲突]] | Memory Conflict Resolution | `L2.P6` | 当新旧记忆矛盾时（用户搬了家、项目改了名），决定以谁为准。 |
| [[遗忘机制]] | Forgetting | `L2.P6` | 按时间衰减、访问频率或置信度主动淘汰低价值记忆。 |
| [[记忆写入策略]] | Memory Write Policy | `L2.P6` | 决定「什么内容值得写进长期记忆、以什么粒度、何时写」的规则或模型。 |
| [[记忆巩固]] | Memory Consolidation | `L2.P6` | 把零散记忆合并、抽象成更高层的结论，模拟睡眠中的记忆固化过程。 |
| [[检查点]] | Checkpoint / State Snapshot | `L2.P7` | 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。 |
| [[工具选择]] | Tool Selection | `L3.P3` | 在给定任务与可用工具集下，选出正确的工具与正确的参数。 |
| [[工具检索]] | Tool Search / Tool RAG | `L3.P3` | 工具数量过多时，先用检索筛出候选工具再交给模型选择。 |
| [[A2A 协议]] | Agent2Agent Protocol | `L3.P4` | 让不同厂商、不同框架的 Agent 相互发现、委派任务并回传结果的协议。 |
| [[OpenAPI 转工具]] | OpenAPI to Tool | `L3.P4` | 把已有的 OpenAPI / Swagger 规范批量转成模型可调用的工具定义。 |
| [[工具定义]] | Tool Definition | `L3.P4` | 用名称、描述、参数 schema 声明一个可被模型调用的能力。 |
| [[权限范围]] | Permission Scope | `L3.P4` | 为每个工具、每个调用方定义可访问的数据与可执行动作的最小集合。 |
| [[模型上下文协议]] | Model Context Protocol | `L3.P4` | 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。 |
| [[沙箱]] | Sandbox | `L3.P4` | 给模型生成的代码划一块隔离区：能跑，但碰不到真实文件、真实网络。 |
| [[MCP 三原语]] | MCP Primitives | `L3.P4` | MCP 把「模型能主动做的事」和「应用能主动取的数据」分成两类，避免什么都塞给模型去决定。 |
| [[代码解释器]] | Code Interpreter | `L3.P4` | 让模型写代码并在隔离环境中执行，用代码代替自然语言做精确计算与数据处理。 |
| [[工具投毒]] | Tool Poisoning | `L3.P4` | 在工具描述或返回内容中埋入指令，诱导模型执行未授权操作或泄露上下文。 |
| [[幂等性]] | Idempotency | `L3.P4` | 保证同一操作重复执行不产生额外副作用，是 Agent 重试机制的安全前提。 |
| [[浏览器自动化]] | Browser Automation | `L3.P4` | 通过 DOM 或无障碍树操作网页，比纯视觉方案更稳定、更省 token。 |
| [[计算机操作]] | Computer Use | `L3.P4` | 通过截图 + 坐标点击操作图形界面，绕开没有 API 的遗留系统。 |
| [[工具返回设计]] | Tool Result Design | `L3.P5` | 决定工具返回什么、返回多少、失败时怎么说——这直接决定了模型的下一步判断质量。 |
| [[工具错误处理]] | Tool Error Handling | `L3.P5` | 定义工具失败时返回什么、模型如何区分「可重试」与「不可重试」。 |
| [[意图分类]] | Intent Classification | `L4.P1` | 在进入 Agent 之前先判断请求属于哪一类，路由到对应处理路径。 |
| [[思维树]] | Tree of Thoughts | `L4.P3` | 把推理展开成树，对多个分支做评估、剪枝与回溯，而非单线前进。 |
| [[语言智能体树搜索]] | LATS | `L4.P3` | 把「试一步、估个分、不行退回来」这种下棋式的搜索，套在 Agent 的动作上。 |
| [[Agent 循环]] | Agent Loop | `L4.P3` | 「想一想、动一下、看看结果」反复循环，直到任务做完或该停为止——所有 Agent 的骨架。 |
| [[ReAct 范式]] | ReAct | `L4.P3` | 把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。 |
| [[任务分解]] | Task Decomposition | `L4.P3` | 把复杂目标拆成可独立验证的子任务，形成可执行的工作分解结构。 |
| [[先规划后执行]] | Plan-and-Execute | `L4.P3` | 先用一次调用产出完整计划，再逐步执行，执行中按需重规划。 |
| [[思维链]] | Chain of Thought | `L4.P3` | 让模型先写出中间推理步骤再给结论，显著提升多步推理任务的准确率。 |
| [[终止判据]] | Termination Criteria | `L4.P3` | 明确定义「任务算完成」「该放弃」「该升级给人」的判据，而不依赖模型的自我感觉。 |
| [[预算控制]] | Budget Control | `L4.P3` | 为每次运行设定步数、token、时间、金额的上限，超限即降级或中止。 |
| [[短路与快速通道]] | Short-circuit / Fast Path | `L4.P3` | 识别出简单请求后直接作答或走固定路径，不进入完整 Agent 循环。 |
| [[计划清单]] | Todo List / Plan Artifact | `L4.P3` | 把计划外化成一份可勾选的清单，作为跨轮次的状态锚点。 |
| [[重试与退避]] | Retry & Backoff | `L4.P5` | 失败后按退避策略重试，并区分可重试错误与必须立刻放弃的错误。 |
| [[熔断]] | Circuit Breaker | `L4.P5` | 下游持续失败时快速断开，避免请求堆积与级联雪崩，并定期试探恢复。 |
| [[反思]] | Reflexion / Self-Refine | `L4.P6` | 让模型评估自己刚才的输出，找出问题并据此重试或修正。 |
| [[重规划]] | Replanning | `L4.P6` | 执行偏离或失败时，基于当前状态重新生成后续计划，而不是硬走原计划。 |
| [[自洽投票]] | Self-Consistency | `L4.P6` | 对同一问题采样多条推理路径，取多数一致的答案。 |
| [[评估-优化循环]] | Evaluator-Optimizer | `L4.P6` | 一个模型负责生成，另一个（或同一模型换角色/换上下文）负责按明确标准评估并反馈。 |
| [[时态状态管理]] | Temporal State | `L4.P7` | 给每一条状态与事实打上时间戳与版本，能回答「当时是什么值」。 |
| [[人在回路]] | Human-in-the-Loop | `L4.P7` | 在关键动作前插入人工审批，或在高风险场景保留持续监督。 |
| [[升级与转人工]] | Escalation / Human Handoff | `L4.P7` | 当置信度低、越权、或反复失败时，把控制权连同上下文完整移交给人。 |
| [[中断与恢复]] | Interrupt & Resume | `L4.P7` | 支持在任意步骤暂停（等待人工输入或外部事件），之后从断点继续。 |
| [[持久化执行]] | Durable Execution | `L4.P7` | 把每一步执行记录为可重放的事件日志，进程崩溃后从最后一步继续，而不是重头再来。 |
| [[路由准确率]] | Routing Accuracy | `L5.P1` | 请求是否被派给了正确的子 Agent 或处理路径。 |
| [[上下文隔离]] | Context Isolation | `L5.P2` | 让子任务在独立的上下文窗口里完成，只把结论回传给主 Agent，中间过程不占用主上下文。 |
| [[对等协作]] | Swarm / Peer-to-Peer | `L5.P3` | 无中心节点，Agent 之间按规则直接把控制权交给下一个合适的 Agent。 |
| [[微服务架构]] | Microservices | `L5.P3` | 把系统拆成独立部署、独立演进的小服务，通过明确定义的接口通信。 |
| [[主管模式]] | Supervisor / Orchestrator-Worker | `L5.P3` | 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。 |
| [[交接]] | Handoff | `L5.P3` | 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。 |
| [[子智能体]] | Subagent | `L5.P3` | 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。 |
| [[任务简报]] | Delegation Brief | `L5.P3` | 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。 |
| [[共享状态]] | Shared State / Blackboard | `L5.P3` | 所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。 |
| [[多智能体系统]] | Multi-Agent System | `L5.P3` | 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。 |
| [[角色设计]] | Role Design | `L5.P3` | 为不同 Agent 设定明确的专业角色与职责边界，而非简单按流程切分。 |
| [[上下文传递]] | Context Transfer | `L5.P5` | 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。 |
| [[错误级联]] | Error Cascade | `L5.P5` | 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。 |
| [[多智能体评测]] | Multi-Agent Evaluation | `L5.P7` | 评测编排路径本身：路由对不对、上下文丢没丢、合流时有没有失真。 |
| [[CI／CD]] | CI/CD | `L6` | 自动化地构建、测试、部署的工程流水线。 |
| [[公开基准]] | Benchmark | `L6` | 标准化的公开评测集，用于横向比较模型或框架的通用能力。 |
| [[统计显著性]] | Statistical Significance | `L6` | 用置信区间判断「提升」是真实效应还是采样噪声。 |
| [[部署]] | Deployment | `L6` | 把 Agent 服务投入生产环境并持续运行。 |
| [[Agent 外壳]] | Harness / Scaffold | `L6` | 包在模型外面的那一层代码：循环、工具注册、上下文拼装、权限、日志，全部由它负责。 |
| [[Agent 评测]] | Evaluation | `L6` | 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。 |
| [[Agent 运行时]] | Agent Runtime | `L6` | 负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。 |
| [[LLM 评审]] | LLM-as-Judge | `L6` | 用模型按预先写好的评分标准（rubric）给回答打分，覆盖没有唯一正确答案的质量维度。 |
| [[可观测性]] | Observability | `L6` | 通过日志、指标、追踪三类信号回答「系统内部正在发生什么」。 |
| [[哨兵集]] | Sentinel Set | `L6` | 从黄金集中挑出的十几条最高危场景，每次部署都跑，分钟级完成。 |
| [[回归门禁]] | Regression Gate | `L6` | 每次部署自动跑哨兵集，质量、安全、延迟、成本任一维度越界则阻断发布。 |
| [[失败分类法]] | Failure Taxonomy | `L6` | 从真实生产错误反推出的一套互斥的失败类型清单，每类配独立判定口径与评测器。 |
