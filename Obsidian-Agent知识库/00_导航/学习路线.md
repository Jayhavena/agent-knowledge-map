# 学习路线 · 从哪开始

> 不要按字母序学。按**依赖关系**学：下层不通，上层只能背名词。

## 阶段一 · 骨架（必须先有）

这一层决定你能不能读懂后面所有东西。任何一个不能用自己的话讲清，先补它。

- [[Agent 循环]] — 「想一想、动一下、看看结果」反复循环，直到任务做完或该停为止——需要多步外部交互的 Agent 的骨架。
- [[ReAct 范式]] — 把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。
- [[思维链]] — 让模型先写出中间推理步骤再给结论，显著提升多步推理任务的准确率。
- [[工具定义]] — 用名称、描述、参数 schema 声明一个可被模型调用的能力。
- [[原生工具调用]] — 模型直接输出结构化调用指令，而非在自由文本里夹带「我想调用某函数」的意图。
- [[上下文工程]] — 系统性决定「每次调用时模型眼前摆什么 token」的工程实践，涵盖选取、排序、压缩、格式化与缓存。
- [[检索增强生成]] — 先从外部知识库检索相关片段，再连同问题一起送入模型生成答案。
- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。
- [[终止判据]] — 明确定义「任务算完成」「该放弃」「该升级给人」的判据，而不依赖模型的自我感觉。

## 阶段二 · 能跑起来

学完这一层，能独立搭一个可用的单 Agent。

- [[工具返回设计]] — 决定工具返回什么、返回多少、失败时怎么说——这直接决定了模型的下一步判断质量。
- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。
- [[先规划后执行]] — 先用一次调用产出完整计划，再逐步执行，执行中按需重规划。
- [[反思]] — 让模型评估自己刚才的输出，找出问题并据此重试或修正。
- [[工作记忆]] — 当前会话内可见的上下文窗口，承载本轮任务的临时状态。
- [[分块]] — 把长文档切成一段段可检索的小块，切多大、从哪切，直接决定检索能不能命中。
- [[重排序]] — 对初筛出的一批候选做逐对精算相关性，再取 Top-K 送入模型。
- [[结构化输出]] — 强制模型只输出符合约定格式的 JSON 等结构，程序可以直接解析，不用从文本里抠。
- [[系统提示]] — 整段对话最前面、优先级最高的那段指令：你是谁、能做什么、不能做什么。
- [[少样本示例]] — 在提示中给出若干输入输出样例，用模式匹配替代显式规则描述。
- [[重试与退避]] — 失败后按退避策略重试，并区分可重试错误与必须立刻放弃的错误。
- [[工具错误处理]] — 定义工具失败时返回什么、模型如何区分「可重试」与「不可重试」。
- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何兼容 MCP 的客户端或 Host 都能用。

## 阶段三 · 跑得住

这一层是 demo 与产品的分界线。缺了它，系统会以「安静地答错」的方式失败。

- [[黄金集]] — 版本化的评测题集，含标准答案与判定口径，是判断回归的唯一依据。
- [[哨兵集]] — 从黄金集中挑出的十几条最高危场景，每次部署都跑，分钟级完成。
- [[LLM 评审]] — 用模型按预先写好的评分标准（rubric）给回答打分，覆盖没有唯一正确答案的质量维度。
- [[确定性评测]] — 对有唯一正确答案的部分（金额、日期、实体、SQL 结果集）用精确断言判定。
- [[失败分类法]] — 从真实生产错误反推出的一套互斥的失败类型清单，每类配独立判定口径与评测器。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。
- [[回归门禁]] — 每次部署自动跑哨兵集，质量、安全、延迟、成本任一维度越界则阻断发布。
- [[漂移检测]] — 持续采样线上真实流量并打分，与离线基线比对，发现无代码变更下的质量滑坡。
- [[金丝雀发布]] — 把新版本先放给一小部分流量，用真实表现决定是否全量。
- [[成本归因]] — 把单次请求的成本拆到每一步、每个工具、每个子 Agent，而不是只看总账单。
- [[时延预算]] — 把端到端时延预算拆分到每一层（入口、检索、模型、工具），并分别设上限。
- [[护栏]] — 在模型入口与出口各设一道检查，拦截违规内容、越权操作与提示攻击。
- [[提示注入]] — 攻击者把指令藏进模型会读到的任何文本（网页、文档、工具返回、文件名），诱导其改变行为。

## 阶段四 · 做出差异

这一层决定你的系统是「又一个套壳」还是「有护城河」。建议按业务需要挑 3–5 个深入，不要全学。

- [[长期记忆]] — 跨会话持久保存的事实、偏好与经历，在需要时被召回进上下文。
- [[记忆写入策略]] — 决定「什么内容值得写进长期记忆、以什么粒度、何时写」的规则或模型。
- [[记忆巩固]] — 把零散记忆合并、抽象成更高层的结论，模拟睡眠中的记忆固化过程。
- [[情景记忆]] — 按「时间 + 事件」组织的历史经历：某次发生了什么、结果如何。
- [[程序记忆]] — 把成功的操作序列沉淀为可复用的「怎么做」，下次直接调用而不重新探索。
- [[图谱增强检索]] — 把文档转成实体-关系图，用图的连通性与社区摘要回答「跨文档、多跳」问题。
- [[代理式检索]] — 让 Agent 自己决定检索什么、检索几次、结果够不够，不够就改写再查。
- [[提示缓存]] — 把稳定前缀（系统提示、工具清单、长文档）的计算结果缓存，后续请求直接复用。
- [[模型路由]] — 按请求的难易程度，把流量分给不同价位、不同能力的模型；简单的走便宜的，难的不凑合。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[主管模式]] — 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。
- [[MCP 三原语]] — MCP 把「模型能主动做的事」和「应用能主动取的数据」分成两类，避免什么都塞给模型去决定。
- [[工具检索]] — 工具数量过多时，先用检索筛出候选工具再交给模型选择。
- [[代码解释器]] — 让模型写代码并在隔离环境中执行，用代码代替自然语言做精确计算与数据处理。
- [[计算机操作]] — 通过截图 + 坐标点击操作图形界面，绕开没有 API 的遗留系统。
- [[人在回路]] — 在关键动作前插入人工审批，或在高风险场景保留持续监督。
