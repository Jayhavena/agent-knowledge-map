# LLM 评审

> **L6 · 系统层 / 评测与质量（环绕全程）** · 质量面 · 核心 / 主流

**LLM-as-Judge**  ·  别名：模型打分、rubric 评分

## 一句话

用模型按预先写好的评分标准（rubric）给回答打分，覆盖没有唯一正确答案的质量维度。

## 具体是什么样

> 「这段回答是否忠实于检索到的原文」没法用规则判，让另一个模型按 rubric 打个分。

## 看不懂？先看这几个

- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。

## 它解决什么问题

相关性、忠实度、有用性这类指标无法用规则判定，人工打分又太贵。

## 它新在哪

新在「规模化」，但它的固有偏差（位置偏好、长度偏好、自我偏好、rubric 敏感）至今没有可靠解。

## 谱系

- **演进** · [[公开基准]]

## 被谁继承

- [[裁判校准]] — 定期测量模型裁判与人工标注的一致率，低于阈值就改 rubric，而不是改阈值。

## 关联概念

- [[引用锚定]] — 要求每个事实性陈述都绑定到检索来源的具体片段，无来源则拒答或标注不确定。
- [[评估-优化循环]] — 一个模型负责生成，另一个（或同一模型换角色/换上下文）负责按明确标准评估并反馈。
- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。
- [[失败分类法]] — 从真实生产错误反推出的一套互斥的失败类型清单，每类配独立判定口径与评测器。
- [[确定性评测]] — 对有唯一正确答案的部分（金额、日期、实体、SQL 结果集）用精确断言判定。
- [[线上采样评测]] — 对生产流量的一部分实时打分，作为质量状态的实时信号。

## 常见误判 / 坑

> [!warning] 坑
> 用同族模型当裁判给自己打分，会系统性高估。必须抽人工标注集校准一致率。
