# 检索增强生成

> **L1.P2 · 上下文层 / 取景** · 定义·质量面 · 核心 / 稳定

**Retrieval-Augmented Generation**  ·  别名：RAG、知识库问答

## 一句话

先从外部知识库检索相关片段，再连同问题一起送入模型生成答案。

## 具体是什么样

> 用户问「我们公司报销上限多少」，先从制度文档里检索出那一段，再让模型照着这段回答。

## 它解决什么问题

模型参数里的知识会过时、会编造、无法覆盖私有数据。

## 它新在哪

已是成熟范式。当前的「新」在它的形态变化：从一次性检索走向代理式检索，从向量检索走向混合与图谱。

## 被谁继承

- [[长上下文]] — 单次可容纳十万至百万 token 的上下文窗口，把「先检索再喂」换成「全部塞进去」。
- [[多模态输入]] — 模型直接读取图像、PDF、音频，跳过「先 OCR 再解析」的传统管线。
- [[上下文工程]] — 系统性决定「每次调用时模型眼前摆什么 token」的工程实践，涵盖选取、排序、压缩、格式化与缓存。
- [[混合检索]] — 同时做关键词（稀疏）与语义（稠密）检索，再融合两路结果。
- [[重排序]] — 对初筛出的一批候选做逐对精算相关性，再取 Top-K 送入模型。
- [[查询改写]] — 在检索前用模型改写、扩展或假设性作答用户问题，缩小「问法」与「文档写法」的语义鸿沟。
- [[图谱增强检索]] — 把文档转成实体-关系图，用图的连通性与社区摘要回答「跨文档、多跳」问题。
- [[代理式检索]] — 让 Agent 自己决定检索什么、检索几次、结果够不够，不够就改写再查。
- [[引用锚定]] — 要求每个事实性陈述都绑定到检索来源的具体片段，无来源则拒答或标注不确定。
- [[长期记忆]] — 跨会话持久保存的事实、偏好与经历，在需要时被召回进上下文。
- [[记忆与 RAG 的边界]] — RAG 是只读的、面向公共知识的检索；记忆是读写双向的、面向个体经历的状态。
- [[工具检索]] — 工具数量过多时，先用检索筛出候选工具再交给模型选择。
- [[Agent 技能]] — 把一套完整做法（说明 + 脚本 + 模板）打包成可按需加载的能力包，平时只占一行摘要。

## 关联概念

- [[分块]] — 把长文档切成一段段可检索的小块，切多大、从哪切，直接决定检索能不能命中。
- [[向量嵌入]] — 把文本映射到高维向量，用余弦相似度衡量语义接近程度。
- [[向量库]] — 专门用来存「语义向量」并快速找出最相似几条的数据库，RAG 和记忆系统都靠它做召回。

## 常见误判 / 坑

> [!warning] 坑
> 把所有「答不准」都归因于生成侧。多数 RAG 质量问题其实在检索侧（召回没中，模型只能编）。
