# 主管模式

> **L5.P3 · 编排层 / 规划** · 机制面 · 核心 / 主流

**Supervisor / Orchestrator-Worker**  ·  别名：编排者、中心调度

## 一句话

一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。

## 它解决什么问题

多 Agent 之间直接互相调用会导致调用图不可控、难以调试。

## 它新在哪

中心化编排是工程上最稳的形态，因为它把「协调」压缩到一个可观测的节点上。

## 谱系

## 关联概念

- [[意图分类]] — 在进入 Agent 之前先判断请求属于哪一类，路由到对应处理路径。
- [[路由准确率]] — 请求是否被派给了正确的子 Agent 或处理路径。
- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。
- [[任务简报]] — 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。
- [[对等协作]] — 无中心节点，Agent 之间按规则直接把控制权交给下一个合适的 Agent。
- [[角色设计]] — 为不同 Agent 设定明确的专业角色与职责边界，而非简单按流程切分。

## 常见误判 / 坑

> [!warning] 坑
> 主管成为上下文与吞吐的瓶颈。所有信息都过它一手，长任务下它会先崩。
