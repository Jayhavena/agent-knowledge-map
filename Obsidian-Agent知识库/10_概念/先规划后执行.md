# 先规划后执行

> **L4.P3 · 控制层 / 规划** · 机制面 · 核心 / 主流

**Plan-and-Execute**  ·  别名：两段式、计划-执行分离

## 一句话

先用一次调用产出完整计划，再逐步执行，执行中按需重规划。

## 它解决什么问题

ReAct 每一步都重新决策，长任务上容易走偏且成本高。

## 它新在哪

把「不确定性」从执行时前移到规划时：代价是计划一旦错，后续全错，因此必须配重规划机制。

## 谱系

- **演进** · [[ReAct 范式]]

## 被谁继承

- [[重规划]] — 执行偏离或失败时，基于当前状态重新生成后续计划，而不是硬走原计划。
- [[任务分解]] — 把复杂目标拆成可独立验证的子任务，形成可执行的工作分解结构。
- [[计划清单]] — 把计划外化成一份可勾选的清单，作为跨轮次的状态锚点。

## 关联概念

- [[推理模型]] — 在给出答案前先生成显式长链思考的模型，把「想多久」变成可调参数。
- [[Agent 循环]] — 「思考 → 行动 → 观察」反复迭代直至终止条件满足的主控循环，是所有 Agent 的骨架。
- [[ReAct 范式]] — 把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。
- [[思维链]] — 让模型先写出中间推理步骤再给结论，显著提升多步推理任务的准确率。

## 常见误判 / 坑

> [!warning] 坑
> 只做一次性规划不重规划。真实环境的反馈会让初始计划在第三步就失效。
