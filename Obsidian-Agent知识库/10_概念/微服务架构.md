# 微服务架构

> **L5.P3 · 编排层 / 规划** · 定义面 · 可选 / 稳定

**Microservices**  ·  别名：服务拆分、分布式系统

## 一句话

把系统拆成独立部署、独立演进的小服务，通过明确定义的接口通信。

## 它解决什么问题

单体系统难以并行开发与独立扩容。

## 它新在哪

它不是 Agent 概念，但多 Agent 的所有坑（服务发现、契约演进、可观测性、级联故障）都是它的旧账。读它是为了少踩一遍。

## 被谁继承

- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[共享状态]] — 所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。
- [[Agent 运行时]] — 负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。

## 关联概念

- [[A2A 协议]] — 让不同厂商、不同框架的 Agent 相互发现、委派任务并回传结果的协议。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 常见误判 / 坑

> [!warning] 坑
> 把「按团队拆」当成分工依据。Agent 应按「能力边界」拆，而非按组织架构。
