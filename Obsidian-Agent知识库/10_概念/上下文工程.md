# 上下文工程

> **L1.P2 · 上下文层 / 取景** · 定义·机制面 · 核心 / 主流

**Context Engineering**  ·  别名：上下文管理、context management

## 一句话

系统性决定「每次调用时模型眼前摆什么 token」的工程实践，涵盖选取、排序、压缩、格式化与缓存。

## 具体是什么样

> 同一个模型，20 篇文档全塞进去 vs 先检索出最相关的 3 篇，后者答对率从 61% 到 84%。差别不在模型，在摆什么。

## 看不懂？先看这几个

- [[基础大模型]] — 通过大规模预训练获得通用语言理解与生成能力的模型，是 Agent 唯一的「思考引擎」。

## 它解决什么问题

模型能力不再稀缺，稀缺的是在正确时刻给出正确且足量的 token；这一层是 Agent 效果方差的最大来源。

## 它新在哪

从「写提示词」升级为「设计一条 token 供给管线」，把检索、记忆召回、压缩、排序统一纳入取舍。

## 被谁继承

- [[上下文压缩]] — 在长会话或多轮工具调用中，把历史压缩成摘要或摘要+关键原文，控制 token 增长。
- [[工作记忆]] — 当前会话内可见的上下文窗口，承载本轮任务的临时状态。
- [[任务简报]] — 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。
- [[Agent 技能]] — 把一套完整做法（说明 + 脚本 + 模板）打包成可按需加载的能力包，平时只占一行摘要。
- [[上下文隔离]] — 让子任务在独立的上下文窗口里完成，只把结论回传给主 Agent，中间过程不占用主上下文。

## 关联概念

- [[中间遗忘]] — 模型对长上下文首尾两端的召回显著优于中段，呈 U 形曲线。
- [[少样本示例]] — 在提示中给出若干输入输出样例，用模式匹配替代显式规则描述。
- [[提示缓存]] — 把稳定前缀（系统提示、工具清单、长文档）的计算结果缓存，后续请求直接复用。
- [[提示词模板]] — 带占位符的提示词字符串，将任务说明与运行时变量拼装成最终输入。
- [[检索增强生成]] — 先从外部知识库检索相关片段，再连同问题一起送入模型生成答案。
- [[用户画像]] — 结构化的用户属性集合：角色、水平、偏好、历史目标。
- [[Agent 外壳]] — 包在模型外面的那一层代码：循环、工具注册、上下文拼装、权限、日志，全部由它负责。

## 常见误判 / 坑

> [!warning] 坑
> 做成「一堆 prompt 模板」的集合，而不是一条有明确容量预算与优先级顺序的管线。
