# 多智能体系统

> **L5.P3 · 编排层 / 规划** · 定义·机制面 · 进阶 / 争议

**Multi-Agent System**  ·  别名：MAS、Agent 协作

## 一句话

多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。

## 它解决什么问题

单 Agent 的上下文与专精能力都有上限，复杂任务需要分工。

## 它新在哪

本质是把分布式系统的老问题（协调、一致性、故障传播）搬进 LLM 场景。多数「新框架」只是在重新发明 actor 模型。

## 被谁继承

- [[主管模式]] — 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。
- [[对等协作]] — 无中心节点，Agent 之间按规则直接把控制权交给下一个合适的 Agent。
- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。
- [[共享状态]] — 所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。
- [[错误级联]] — 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。
- [[路由准确率]] — 请求是否被派给了正确的子 Agent 或处理路径。
- [[角色设计]] — 为不同 Agent 设定明确的专业角色与职责边界，而非简单按流程切分。
- [[多智能体评测]] — 评测编排路径本身：路由对不对、上下文丢没丢、合流时有没有失真。
- [[评测三层级]] — 工具级、单 Agent 级、多 Agent 级各有一套黄金集、评测器与晋级标准，三层都要跑。

## 关联概念

- [[A2A 协议]] — 让不同厂商、不同框架的 Agent 相互发现、委派任务并回传结果的协议。
- [[任务分解]] — 把复杂目标拆成可独立验证的子任务，形成可执行的工作分解结构。
- [[评估-优化循环]] — 一个模型负责生成，另一个（或同一模型换角色/换上下文）负责按明确标准评估并反馈。
- [[上下文隔离]] — 让子任务在独立的上下文窗口里完成，只把结论回传主循环，中间过程不污染主上下文。
- [[微服务架构]] — 把系统拆成独立部署、独立演进的小服务，通过明确定义的接口通信。

## 常见误判 / 坑

> [!warning] 坑
> 为用多 Agent 而用多 Agent。多数任务用单 Agent + 好工具 + 好上下文更快更稳。先证明单 Agent 不行。
