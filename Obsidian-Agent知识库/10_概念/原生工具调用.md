# 原生工具调用

> **L0.P4 · 模型层 / 行动** · 机制面 · 核心 / 稳定

**Native Tool / Function Calling**  ·  别名：function calling、工具调用

## 一句话

模型直接输出结构化调用指令，而非在自由文本里夹带「我想调用某函数」的意图。

## 具体是什么样

> 模型不再输出「我想查一下订单」这句话，而是输出 {"name":"query_order","arguments":{"id":"A123"}}，程序可以直接执行。

## 看不懂？先看这几个

- [[基础大模型]] — 通过大规模预训练获得通用语言理解与生成能力的模型，是 Agent 唯一的「思考引擎」。

## 它解决什么问题

从自然语言里正则解析调用意图，脆弱、无法可靠处理多参数与并行调用。

## 它新在哪

让「调用」成为模型的一等输出格式，是 Agent 从演示走向工程化的前提。

## 谱系

- **替代** · [[提示词模板]]

## 被谁继承

- [[工具定义]] — 用名称、描述、参数 schema 声明一个可被模型调用的能力。
- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。

## 关联概念

- [[上下文压缩]] — 在长会话或多轮工具调用中，把历史压缩成摘要或摘要+关键原文，控制 token 增长。
- [[结构化输出]] — 强制模型只输出符合约定格式的 JSON 等结构，程序可以直接解析，不用从文本里抠。
- [[检查点]] — 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。
- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。
- [[工具错误处理]] — 定义工具失败时返回什么、模型如何区分「可重试」与「不可重试」。
- [[ReAct 范式]] — 把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 常见误判 / 坑

> [!warning] 坑
> 以为有了原生调用就不用设计工具描述。描述质量仍直接决定工具选择准确率。
