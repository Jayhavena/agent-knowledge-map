# 熔断

> **L4.P5 · 控制层 / 观察** · 运维面 · 进阶 / 稳定

**Circuit Breaker**  ·  别名：快速失败、降级开关

## 一句话

下游持续失败时快速断开，避免请求堆积与级联雪崩，并定期试探恢复。

## 具体是什么样

> 下游连续失败 5 次，直接断开十分钟不再尝试，免得请求堆积把整个系统拖死。

## 看不懂？先看这几个

- [[重试与退避]] — 失败后按退避策略重试，并区分可重试错误与必须立刻放弃的错误。

## 它解决什么问题

重试风暴会让一个已经过载的依赖彻底死亡。

## 它新在哪

老模式，新场景：LLM API 的限流是常态，熔断常常比重试更重要。

## 谱系

- **并行** · [[重试与退避]]

## 关联概念

- [[模型路由]] — 按请求的难易程度，把流量分给不同价位、不同能力的模型；简单的走便宜的，难的不凑合。
- [[重试与退避]] — 失败后按退避策略重试，并区分可重试错误与必须立刻放弃的错误。
- [[升级与转人工]] — 当置信度低、越权、或反复失败时，把控制权连同上下文完整移交给人。
- [[成本预算]] — 为每个租户、每个场景设定成本上限，并在接近上限时降级而非熔断。

## 常见误判 / 坑

> [!warning] 坑
> 熔断后直接报错给用户。应有降级路径（换模型、走缓存、转人工）。
