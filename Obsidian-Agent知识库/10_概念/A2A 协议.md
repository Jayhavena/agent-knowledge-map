# A2A 协议

> **L3.P4 · 工具层 / 行动** · 定义面 · 可选 / 前沿

**Agent2Agent Protocol**  ·  别名：智能体互操作、agent card

## 一句话

让不同厂商、不同框架的 Agent 相互发现、委派任务并回传结果的协议。

## 具体是什么样

> 你们公司的采购 Agent 要调供应商的报价 Agent，两边是不同厂商不同框架，靠 A2A 互相发现并派活。

## 看不懂？先看这几个

- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。

## 它解决什么问题

每个 Agent 框架自成生态，跨组织协作时没有共同语言。

## 它新在哪

MCP 解决「模型 ↔ 工具」，A2A 解决「Agent ↔ Agent」。区分这两者，比记住协议细节更重要。

## 谱系

- **并行** · [[模型上下文协议]]

## 被谁继承

- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。

## 关联概念

- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[微服务架构]] — 把系统拆成独立部署、独立演进的小服务，通过明确定义的接口通信。

## 常见误判 / 坑

> [!warning] 坑
> 在没有跨组织需求时引入。内部多 Agent 用进程内调用即可，协议层只会增加延迟与调试成本。
