# MCP 三原语

> **L3.P4 · 工具层 / 行动** · 机制面 · 进阶 / 主流

**MCP Primitives**  ·  别名：tools / resources / prompts

## 一句话

MCP 把「模型能主动做的事」和「应用能主动取的数据」分成两类，避免什么都塞给模型去决定。

## 具体是什么样

> 「读这篇文档」做成 resource 由客户端挂载，不占模型的决策预算；「发邮件」才做成 tool，让模型自己决定要不要发。

## 看不懂？先看这几个

- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。

## 它解决什么问题

如果所有能力都做成工具，模型每次读一份文档都要先做一次决策，又贵又容易选错。

## 它新在哪

它区分了「模型主动做」与「应用主动取」：resources 由客户端挂载，不消耗模型的决策预算。

## 关联概念

- [[Agent 技能]] — 把一套完整做法（说明 + 脚本 + 模板）打包成可按需加载的能力包，平时只占一行摘要。
- [[工具检索]] — 工具数量过多时，先用检索筛出候选工具再交给模型选择。
- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。
- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。

## 常见误判 / 坑

> [!warning] 坑
> 把只读数据也做成 tool。每次读取都变成一次决策，成本上升且容易选错。
