# 任务简报

> **L5.P3 · 编排层 / 规划** · 机制·质量面 · 进阶 / 主流

**Delegation Brief**  ·  别名：交接包、子任务契约

## 一句话

派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。

## 具体是什么样

> 派活时写清：目标（查清退款率上涨原因）、边界（只看华东区）、输出格式（三条结论 + 数据来源）。

## 看不懂？先看这几个

- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。

## 它解决什么问题

子 Agent 没有主 Agent 的上下文，简报含糊会导致它朝错误方向努力。

## 它新在哪

它是「上下文工程」在多 Agent 场景的投影：跨 Agent 传递上下文不是复制粘贴，而是重新组装。

## 关联概念

- [[任务分解]] — 把复杂目标拆成可独立验证的子任务，形成可执行的工作分解结构。
- [[主管模式]] — 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。
- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。
- [[角色设计]] — 为不同 Agent 设定明确的专业角色与职责边界，而非简单按流程切分。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。

## 常见误判 / 坑

> [!warning] 坑
> 把主 Agent 的全部历史塞给子 Agent。既浪费 token，又让子 Agent 被无关信息带偏。
