# Agent 评测

> **L6 · 系统层 / 评测与质量（环绕全程）** · 质量面 · 核心 / 主流

**Evaluation**  ·  别名：质量评估、eval

## 一句话

用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。

## 它解决什么问题

监控只能回答「有没有响应」，无法回答「答案对不对」。

## 它新在哪

它从「上线前的 QA 环节」变成「贯穿全生命周期的操作系统」：CI 门禁、金丝雀、线上采样、反馈回流。

## 谱系

- **演进** · [[公开基准]]
- **组合** · 回归测试（软件工程，图外旧概念）

## 被谁继承

- [[提示词自动优化]] — 用评测信号驱动搜索或梯度式改写提示词，替代人工试错。
- [[多智能体评测]] — 评测编排路径本身：路由对不对、上下文丢没丢、合流时有没有失真。
- [[失败分类法]] — 从真实生产错误反推出的一套互斥的失败类型清单，每类配独立判定口径与评测器。
- [[评测三层级]] — 工具级、单 Agent 级、多 Agent 级各有一套黄金集、评测器与晋级标准，三层都要跑。
- [[回归门禁]] — 每次部署自动跑哨兵集，质量、安全、延迟、成本任一维度越界则阻断发布。
- [[漂移检测]] — 持续采样线上真实流量并打分，与离线基线比对，发现无代码变更下的质量滑坡。
- [[A／B 实验]] — 把真实流量分成两组，用同一套打分器比较两个版本的实际表现。
- [[评测过拟合]] — 系统被优化成「专门讨好评测集的样子」，指标上涨但真实表现退化。

## 关联概念

- [[模型路由]] — 按请求难度把流量分发给不同价位与能力的模型。
- [[大海捞针测试]] — 在超长文本的随机位置埋入一个事实，考察模型能否准确取出。
- [[少样本示例]] — 在提示中给出若干输入输出样例，用模式匹配替代显式规则描述。
- [[提示词版本管理]] — 把提示词当作代码：纳入版本控制、可评审、可回滚、每次变更跑回归评测。
- [[引用锚定]] — 要求每个事实性陈述都绑定到检索来源的具体片段，无来源则拒答或标注不确定。
- [[结构化输出]] — 强制模型输出符合给定 schema 的 JSON 或其他格式，供下游程序直接消费。
- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。
- [[评估-优化循环]] — 一个模型负责生成，另一个（或同一模型换角色/换上下文）负责按明确标准评估并反馈。
- [[路由准确率]] — 请求是否被派给了正确的子 Agent 或处理路径。
- [[错误级联]] — 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。
- [[Agent 外壳]] — 包在模型外面的那一层代码：循环、工具注册、上下文拼装、权限、日志，全部由它负责。
- [[CI／CD]] — 自动化地构建、测试、部署的工程流水线。
- [[LLM 评审]] — 用模型按预先写好的评分标准（rubric）给回答打分，覆盖没有唯一正确答案的质量维度。
- [[公开基准]] — 标准化的公开评测集，用于横向比较模型或框架的通用能力。
- [[可观测性]] — 通过日志、指标、追踪三类信号回答「系统内部正在发生什么」。
- [[哨兵集]] — 从黄金集中挑出的十几条最高危场景，每次部署都跑，分钟级完成。
- [[确定性评测]] — 对有唯一正确答案的部分（金额、日期、实体、SQL 结果集）用精确断言判定。
- [[线上采样评测]] — 对生产流量的一部分实时打分，作为质量状态的实时信号。
- [[统计显著性]] — 用置信区间判断「提升」是真实效应还是采样噪声。
- [[裁判校准]] — 定期测量模型裁判与人工标注的一致率，低于阈值就改 rubric，而不是改阈值。
- [[轨迹复盘]] — 对一次失败运行做逐步回放，定位「哪一步开始偏离」，而不是只看最终输出。
- [[金丝雀发布]] — 把新版本先放给一小部分流量，用真实表现决定是否全量。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。
- [[黄金集]] — 版本化的评测题集，含标准答案与判定口径，是判断回归的唯一依据。

## 常见误判 / 坑

> [!warning] 坑
> 把「准确性」当作单一指标。不拆成可归因的失败类型，指标掉了也不知道改哪里。
