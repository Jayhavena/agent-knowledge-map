# 权限范围

> **L3.P4 · 工具层 / 行动** · 安全面 · 核心 / 主流

**Permission Scope**  ·  别名：最小权限、授权粒度

## 一句话

为每个工具、每个调用方定义可访问的数据与可执行动作的最小集合。

## 具体是什么样

> 查订单的 Agent 不该有删库权限；处理 A 客户的会话，不该读到 B 客户的数据。

## 看不懂？先看这几个

- [[工具定义]] — 用名称、描述、参数 schema 声明一个可被模型调用的能力。

## 它解决什么问题

Agent 常被授予「服务账号全部权限」，一次注入就能横向访问所有资源。

## 它新在哪

从静态 RBAC 演进出「按任务临时授权」：权限随 Agent 的当前目标收窄，任务结束即失效。

## 谱系

- **特化** · [[护栏]]

## 被谁继承

- [[沙箱]] — 给模型生成的代码划一块隔离区：能跑，但碰不到真实文件、真实网络。
- [[数据外泄]] — 攻击者通过让 Agent 访问外部 URL、写文件、发请求，把上下文中的敏感数据带出去。
- [[多租户隔离]] — 保证不同租户的上下文、记忆、工具权限与配额互不可见。

## 关联概念

- [[工具投毒]] — 在工具描述或返回内容中埋入指令，诱导模型执行未授权操作或泄露上下文。
- [[幂等性]] — 保证同一操作重复执行不产生额外副作用，是 Agent 重试机制的安全前提。
- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。
- [[人在回路]] — 在关键动作前插入人工审批，或在高风险场景保留持续监督。
- [[审计日志]] — 不可篡改地记录「谁在何时让 Agent 做了什么、影响了哪些数据」。
- [[护栏]] — 在模型入口与出口各设一道检查，拦截违规内容、越权操作与提示攻击。

## 常见误判 / 坑

> [!warning] 坑
> 按角色授权而不按任务授权。同一个 Agent 在处理不同用户请求时，权限应当不同。
