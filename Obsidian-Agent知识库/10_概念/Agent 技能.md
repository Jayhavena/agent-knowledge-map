# Agent 技能

> **L1.P2 · 上下文层 / 取景** · 机制·成本面 · 进阶 / 前沿

**Agent Skills**  ·  别名：Skills、渐进披露、progressive disclosure

## 一句话

把一套完整做法（说明 + 脚本 + 模板）打包成可按需加载的能力包，平时只占一行摘要。

## 具体是什么样

> 把「写周报」的完整做法（模板 + 取数脚本 + 格式要求）打包成一个技能，平时只占一行说明，用到才展开。

## 看不懂？先看这几个

- [[上下文工程]] — 系统性决定「每次调用时模型眼前摆什么 token」的工程实践，涵盖选取、排序、压缩、格式化与缓存。

## 它解决什么问题

把所有知识都塞进开头那段指令，既撑爆上下文，又让模型在无关场景被干扰。

## 它新在哪

它是上下文工程里最省钱的一招：用完再加载，而不是提前全都给。本质是分页，不是新能力。

## 谱系

- **特化** · [[上下文工程]]
- **并行** · [[检索增强生成]]

## 关联概念

- [[上下文压缩]] — 在长会话或多轮工具调用中，把历史压缩成摘要或摘要+关键原文，控制 token 增长。
- [[上下文工程]] — 系统性决定「每次调用时模型眼前摆什么 token」的工程实践，涵盖选取、排序、压缩、格式化与缓存。
- [[工具检索]] — 工具数量过多时，先用检索筛出候选工具再交给模型选择。
- [[MCP 三原语]] — MCP 把「模型能主动做的事」和「应用能主动取的数据」分成两类，避免什么都塞给模型去决定。

## 常见误判 / 坑

> [!warning] 坑
> 技能包写成没人知道何时该用的长文档。摘要行必须写「什么时候用」，而不是「这是什么」。
