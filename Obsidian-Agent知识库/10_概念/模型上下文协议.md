# 模型上下文协议

> **L3.P4 · 工具层 / 行动** · 定义·机制面 · 核心 / 主流

**Model Context Protocol**  ·  别名：MCP

## 一句话

把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。

## 它解决什么问题

M 个模型 × N 个工具需要 M×N 套适配代码，且每家的调用格式各不相同。

## 它新在哪

它不是新能力，而是把 USB 式的接口经济学引入 Agent 工具层——价值在生态，不在协议本身。

## 被谁继承

- [[MCP 三原语]] — MCP 定义的三种交互对象：tools（可执行动作）、resources（可读数据）、prompts（可复用模板）。
- [[A2A 协议]] — 让不同厂商、不同框架的 Agent 相互发现、委派任务并回传结果的协议。
- [[工具投毒]] — 在工具描述或返回内容中埋入指令，诱导模型执行未授权操作或泄露上下文。

## 关联概念

- [[原生工具调用]] — 模型直接输出结构化调用指令，而非在自由文本里夹带「我想调用某函数」的意图。
- [[指令层级]] — 明确定义系统指令、开发者指令、用户指令、工具返回内容之间的优先级与冲突裁决规则。
- [[工具检索]] — 工具数量过多时，先用检索筛出候选工具再交给模型选择。
- [[OpenAPI 转工具]] — 把已有的 OpenAPI / Swagger 规范批量转成模型可调用的工具定义。
- [[工具定义]] — 用名称、描述、参数 schema 声明一个可被模型调用的能力。
- [[权限范围]] — 为每个工具、每个调用方定义可访问的数据与可执行动作的最小集合。

## 常见误判 / 坑

> [!warning] 坑
> 把它当 RPC 用。MCP 的设计假设是「模型会读描述自己决定调不调」，过度细粒度会让工具选择崩塌。
