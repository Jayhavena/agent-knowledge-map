# 子智能体

> **L5.P3 · 编排层 / 规划** · 机制·成本面 · 核心 / 主流

**Subagent**  ·  别名：派生 Agent、专门代理

## 一句话

为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。

## 具体是什么样

> 主 Agent 需要读 20 份文档，派生一个子 Agent 去读，只把「这 20 份里跟退款有关的是第 3、7、15 份」带回来。

## 看不懂？先看这几个

- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。

## 它解决什么问题

主 Agent 的上下文会被子任务的中间过程污染，且窗口有限。

## 它新在哪

它是「上下文隔离」最有效的工程手段：不只是并行，更是把噪声挡在主循环之外。

## 谱系

- **演进** · [[任务分解]]
- **特化** · [[多智能体系统]]

## 被谁继承

- [[上下文隔离]] — 让子任务在独立的上下文窗口里完成，只把结论回传给主 Agent，中间过程不占用主上下文。

## 关联概念

- [[任务分解]] — 把复杂目标拆成可独立验证的子任务，形成可执行的工作分解结构。
- [[计划清单]] — 把计划外化成一份可勾选的清单，作为跨轮次的状态锚点。
- [[主管模式]] — 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。
- [[任务简报]] — 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。

## 常见误判 / 坑

> [!warning] 坑
> 子 Agent 数量失控。每个都带回一份摘要，主 Agent 反而被汇总结果淹没。
