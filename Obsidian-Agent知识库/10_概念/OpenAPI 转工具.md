# OpenAPI 转工具

> **L3.P4 · 工具层 / 行动** · 机制面 · 可选 / 主流

**OpenAPI to Tool**  ·  别名：API 自动封装、spec 驱动

## 一句话

把已有的 OpenAPI / Swagger 规范批量转成模型可调用的工具定义。

## 具体是什么样

> 公司有 200 个 REST 接口，用脚本把 OpenAPI 规范批量转成工具定义，一天就能接上。

## 看不懂？先看这几个

- [[工具定义]] — 用名称、描述、参数 schema 声明一个可被模型调用的能力。

## 它解决什么问题

手写每个工具的 schema 与描述，在大型 API 面前不现实。

## 它新在哪

看起来是效率工具，实际是陷阱放大器：机械转换出来的 200 个工具会直接摧毁选择准确率。

## 关联概念

- [[工具检索]] — 工具数量过多时，先用检索筛出候选工具再交给模型选择。
- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。
- [[工具定义]] — 用名称、描述、参数 schema 声明一个可被模型调用的能力。

## 常见误判 / 坑

> [!warning] 坑
> 全量转换。应该先按任务域裁剪、合并、重写描述，再加一层工具检索。
