# 交接

> **L5.P3 · 编排层 / 规划** · 机制·质量面 · 核心 / 主流

**Handoff**  ·  别名：转交、控制权转移

## 一句话

把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。

## 具体是什么样

> 把「用户已确认订单号 A123、已排除是物流问题」这两条一起交给下一环节，而不是只丢一句「你来处理」。

## 看不懂？先看这几个

- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。

## 它解决什么问题

分工之后必须有明确的责任转移点，否则任务会掉在地上。

## 它新在哪

关键不在「怎么转」，而在「转什么」：交接包的内容质量决定了多 Agent 系统的可用性。

## 谱系

## 被谁继承

- [[任务简报]] — 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。

## 关联概念

- [[A2A 协议]] — 让不同厂商、不同框架的 Agent 相互发现、委派任务并回传结果的协议。
- [[主管模式]] — 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。
- [[共享状态]] — 所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[对等协作]] — 无中心节点，Agent 之间按规则直接把控制权交给下一个合适的 Agent。
- [[错误级联]] — 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。

## 常见误判 / 坑

> [!warning] 坑
> 只传任务描述不传约束与已确认事实。接收方会重复已经排除的路径，或违反上游已声明的边界。
