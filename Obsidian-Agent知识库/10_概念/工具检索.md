# 工具检索

> **L3.P3 · 工具层 / 规划** · 质量面 · 进阶 / 前沿

**Tool Search / Tool RAG**  ·  别名：动态工具加载、工具按需暴露

## 一句话

工具数量过多时，先用检索筛出候选工具再交给模型选择。

## 具体是什么样

> 接了 120 个 MCP 工具，全塞进上下文既贵又容易选错；先按用户意图检索出 8 个候选，再让模型挑。

## 看不懂？先看这几个

- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。

## 它解决什么问题

上百个 MCP 工具全量注入，既吃掉上下文预算，又显著降低选择准确率。

## 它新在哪

把 RAG 的思路从「检索知识」迁移到「检索能力」，是工具规模化后的必然产物。

## 谱系

- **演进** · [[工具选择]]

## 关联概念

- [[Agent 技能]] — 把一套完整做法（说明 + 脚本 + 模板）打包成可按需加载的能力包，平时只占一行摘要。
- [[代理式检索]] — 让 Agent 自己决定检索什么、检索几次、结果够不够，不够就改写再查。
- [[工具选择]] — 在给定任务与可用工具集下，选出正确的工具与正确的参数。
- [[MCP 三原语]] — MCP 把「模型能主动做的事」和「应用能主动取的数据」分成两类，避免什么都塞给模型去决定。
- [[OpenAPI 转工具]] — 把已有的 OpenAPI / Swagger 规范批量转成模型可调用的工具定义。
- [[模型上下文协议]] — 把「模型 ↔ 外部能力」的接入方式标准化：一次实现服务端，任何客户端都能用。

## 常见误判 / 坑

> [!warning] 坑
> 检索错了工具就等于能力缺失，且失败表现是「模型说做不到」，很难归因到检索层。
