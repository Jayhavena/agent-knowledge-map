# 终止判据

> **L4.P3 · 控制层 / 规划** · 质量·成本面 · 核心 / 主流

**Termination Criteria**  ·  别名：何时停、停止条件

## 一句话

明确定义「任务算完成」「该放弃」「该升级给人」的判据，而不依赖模型的自我感觉。

## 具体是什么样

> 「数据到手就算完成」「重试三次仍失败就转人工」「预算超了立刻停」——三条都写进代码，而不是等模型自己说完了。

## 看不懂？先看这几个

- [[Agent 循环]] — 「想一想、动一下、看看结果」反复循环，直到任务做完或该停为止——所有 Agent 的骨架。

## 它解决什么问题

模型倾向于一直做下去或过早宣布完成，两种失败都很常见且都很贵。

## 它新在哪

它是最被低估的设计点：一个 Agent 系统的可靠性上限，常常由终止判据的质量决定，而非模型能力。

## 谱系

- **特化** · [[Agent 循环]]

## 被谁继承

- [[预算控制]] — 为每次运行设定步数、token、时间、金额的上限，超限即降级或中止。
- [[升级与转人工]] — 当置信度低、越权、或反复失败时，把控制权连同上下文完整移交给人。

## 关联概念

- [[工具错误处理]] — 定义工具失败时返回什么、模型如何区分「可重试」与「不可重试」。
- [[Agent 循环]] — 「想一想、动一下、看看结果」反复循环，直到任务做完或该停为止——所有 Agent 的骨架。
- [[短路与快速通道]] — 识别出简单请求后直接作答或走固定路径，不进入完整 Agent 循环。
- [[重规划]] — 执行偏离或失败时，基于当前状态重新生成后续计划，而不是硬走原计划。
- [[对等协作]] — 无中心节点，Agent 之间按规则直接把控制权交给下一个合适的 Agent。

## 常见误判 / 坑

> [!warning] 坑
> 只用「模型输出了 final answer」作为终止。模型会在没做完时也输出 final answer。
