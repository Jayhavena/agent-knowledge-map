# 上下文传递

> **L5.P5 · 编排层 / 观察** · 质量面 · 核心 / 主流

**Context Transfer**  ·  别名：跨 Agent 上下文、状态同步

## 一句话

在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。

## 具体是什么样

> 上游说「已排除物流问题」，下游如果不知道这条，会把物流再查一遍，浪费两轮。

## 看不懂？先看这几个

- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。

## 它解决什么问题

多 Agent 系统的失真几乎都发生在合流处，而非分工处。

## 它新在哪

它是多 Agent 的「grounding 问题」：可独立度量为 context transfer accuracy，且是新增的失败面。

## 谱系

- **特化** · [[交接]]

## 关联概念

- [[上下文隔离]] — 让子任务在独立的上下文窗口里完成，只把结论回传给主 Agent，中间过程不占用主上下文。
- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。
- [[任务简报]] — 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。
- [[共享状态]] — 所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。
- [[错误级联]] — 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。
- [[多智能体评测]] — 评测编排路径本身：路由对不对、上下文丢没丢、合流时有没有失真。

## 常见误判 / 坑

> [!warning] 坑
> 只验证「消息发出去了」，不验证「对方理解正确」。需要在下游断言关键约束是否仍在。
