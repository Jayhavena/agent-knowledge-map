# 浏览器自动化

> **L3.P4 · 工具层 / 行动** · 机制面 · 进阶 / 主流

**Browser Automation**  ·  别名：网页智能体、Playwright 驱动

## 一句话

通过 DOM 或无障碍树操作网页，比纯视觉方案更稳定、更省 token。

## 具体是什么样

> 同样是操作网页，读 DOM 结构比截图点坐标稳得多：按钮改位置了也照样点得到。

## 看不懂？先看这几个

- [[计算机操作]] — 通过截图 + 坐标点击操作图形界面，绕开没有 API 的遗留系统。

## 它解决什么问题

计算机操作依赖截图，慢且脆；网页有结构化表示可用。

## 它新在哪

是 computer use 的窄化特化：牺牲通用性换取可靠性，工程上几乎总是更优选择。

## 谱系

- **演进** · [[计算机操作]]

## 关联概念

- [[多模态输入]] — 模型直接读取图像、PDF、音频，跳过「先 OCR 再解析」的传统管线。
- [[提示注入]] — 攻击者把指令藏进模型会读到的任何文本（网页、文档、工具返回、文件名），诱导其改变行为。
- [[沙箱]] — 给模型生成的代码划一块隔离区：能跑，但碰不到真实文件、真实网络。
- [[计算机操作]] — 通过截图 + 坐标点击操作图形界面，绕开没有 API 的遗留系统。

## 常见误判 / 坑

> [!warning] 坑
> 忽略网页里的隐藏文本。抓取到的 DOM 里可能藏着针对 Agent 的注入指令。
