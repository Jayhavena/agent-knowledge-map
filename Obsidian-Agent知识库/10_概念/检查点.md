# 检查点

> **L2.P7 · 记忆层 / 交付** · 运维面 · 核心 / 主流

**Checkpoint / State Snapshot**  ·  别名：状态快照、断点续跑

## 一句话

在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。

## 它解决什么问题

Agent 一次运行可能十分钟、几十次工具调用，中途失败重头再来不可接受。

## 它新在哪

从「数据库事务」借来的概念，在 Agent 语境下还多了一个用途：重放失败轨迹做根因分析。

## 谱系

- **特化** · 持久化（数据库，图外旧概念）

## 被谁继承

- [[中断与恢复]] — 支持在任意步骤暂停（等待人工输入或外部事件），之后从断点继续。
- [[持久化执行]] — 把每一步执行记录为可重放的事件日志，进程崩溃后从最后一步继续，而不是重头再来。

## 关联概念

- [[工作记忆]] — 当前会话内可见的上下文窗口，承载本轮任务的临时状态。
- [[幂等性]] — 保证同一操作重复执行不产生额外副作用，是 Agent 重试机制的安全前提。
- [[重试与退避]] — 失败后按退避策略重试，并区分可重试错误与必须立刻放弃的错误。
- [[升级与转人工]] — 当置信度低、越权、或反复失败时，把控制权连同上下文完整移交给人。
- [[时态状态管理]] — 给每一条状态与事实打上时间戳与版本，能回答「当时是什么值」。
- [[共享状态]] — 所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。
- [[Agent 运行时]] — 负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 常见误判 / 坑

> [!warning] 坑
> 只存消息历史，不存工具调用的副作用。恢复后会用「已执行过」的状态重复执行有副作用的操作。
