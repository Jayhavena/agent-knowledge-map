# 任务分解

> **L4.P3 · 控制层 / 规划** · 机制面 · 核心 / 主流

**Task Decomposition**  ·  别名：子任务拆分、分而治之

## 一句话

把复杂目标拆成可独立验证的子任务，形成可执行的工作分解结构。

## 它解决什么问题

一次性处理复杂目标容易遗漏约束、无法中途校验。

## 它新在哪

新在「拆分的粒度由可验证性决定」——每个子任务都要有明确的完成判据，否则拆了也白拆。

## 谱系

- **特化** · [[先规划后执行]]

## 被谁继承

- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[主管模式]] — 一个中心 Agent 负责拆解与派发，子 Agent 执行后把结果汇回主管。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。

## 关联概念

- [[先规划后执行]] — 先用一次调用产出完整计划，再逐步执行，执行中按需重规划。
- [[计划清单]] — 把计划外化成一份可勾选的清单，作为跨轮次的状态锚点。
- [[任务简报]] — 派发子任务时给出的结构化说明：目标、边界、已知事实、输出格式、验收标准。

## 常见误判 / 坑

> [!warning] 坑
> 按「动作」拆而不是按「可验证的成果」拆。前者会产生几十个无法判断是否完成的步骤。
