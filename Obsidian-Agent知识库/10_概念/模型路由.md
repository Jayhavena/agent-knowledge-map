# 模型路由

> **L0.P2 · 模型层 / 取景** · 成本·时延面 · 进阶 / 主流

**Model Routing**  ·  别名：模型级联、大小模型协同、LLM router

## 一句话

按请求难度把流量分发给不同价位与能力的模型。

## 它解决什么问题

用最强模型跑全部请求，成本与延迟都不可接受；用小模型兜底又怕质量塌方。

## 它新在哪

把「选哪个模型」从架构期的人工决策，变成运行时的可调策略；本质是级联模式在 LLM 上的特化。

## 谱系

- **特化** · 级联分类器（机器学习，图外旧概念）

## 被谁继承

- [[短路与快速通道]] — 识别出简单请求后直接作答或走固定路径，不进入完整 Agent 循环。
- [[意图分类]] — 在进入 Agent 之前先判断请求属于哪一类，路由到对应处理路径。

## 关联概念

- [[基础大模型]] — 通过大规模预训练获得通用语言理解与生成能力的模型，是 Agent 唯一的「思考引擎」。
- [[小模型·端侧模型]] — 参数量小、可本地部署的模型，用于延迟敏感、隐私敏感或高频廉价任务。
- [[熔断]] — 下游持续失败时快速断开，避免请求堆积与级联雪崩，并定期试探恢复。
- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。
- [[成本归因]] — 把单次请求的成本拆到每一步、每个工具、每个子 Agent，而不是只看总账单。
- [[成本预算]] — 为每个租户、每个场景设定成本上限，并在接近上限时降级而非熔断。

## 常见误判 / 坑

> [!warning] 坑
> 路由分类器自身的误判会以「静默劣化」出现——请求被送到弱模型并给出看似合理的错答案。路由必须单独评测。
