# 持久化执行

> **L4.P7 · 控制层 / 交付** · 运维面 · 进阶 / 主流

**Durable Execution**  ·  别名：工作流引擎、确定性重放

## 一句话

把每一步执行记录为可重放的事件日志，进程崩溃后从最后一步继续，而不是重头再来。

## 具体是什么样

> 每一步都记进事件日志，机器重启后按日志重放，已经执行过的步骤不再重跑。

## 看不懂？先看这几个

- [[检查点]] — 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。

## 它解决什么问题

Agent 运行在不可靠的进程里，长任务中途崩溃是常态而非例外。

## 它新在哪

从工作流引擎（Temporal 等）迁移而来。关键洞察是：LLM 的输出不可重放，必须被记录而非重算。

## 关联概念

- [[检查点]] — 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。
- [[幂等性]] — 保证同一操作重复执行不产生额外副作用，是 Agent 重试机制的安全前提。
- [[中断与恢复]] — 支持在任意步骤暂停（等待人工输入或外部事件），之后从断点继续。
- [[时态状态管理]] — 给每一条状态与事实打上时间戳与版本，能回答「当时是什么值」。
- [[Agent 运行时]] — 负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 常见误判 / 坑

> [!warning] 坑
> 重放时重新调用 LLM。同一输入未必得到同一输出，恢复后的状态会与原轨迹分叉。
