# Agent 循环

> **L4.P3 · 控制层 / 规划** · 定义·机制面 · 核心 / 稳定

**Agent Loop**  ·  别名：主循环、ReAct 循环、think-act-observe

## 一句话

「想一想、动一下、看看结果」反复循环，直到任务做完或该停为止——需要多步外部交互的 Agent 的骨架。

## 具体是什么样

> 「查一下上周退款率为什么涨了」——模型先查指标、发现集中在某商品、再查该商品评价、最后给结论，中间每步都看结果再决定下一步。

## 看不懂？先看这几个

- [[ReAct 范式]] — 把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。

## 它解决什么问题

单次问答无法完成需要多步外部交互的任务；必须有一个能根据反馈继续决策的循环。

## 它新在哪

它的结构其实二十年没变（感知-决策-执行）。真正在演化的只有三件事：终止判据、预算控制、失败恢复。

## 谱系

- **并行** · 控制回路（控制论，图外旧概念）

## 被谁继承

- [[终止判据]] — 明确定义「任务算完成」「该放弃」「该升级给人」的判据，而不依赖模型的自我感觉。
- [[短路与快速通道]] — 识别出简单请求后直接作答或走固定路径，不进入完整 Agent 循环。
- [[Agent 外壳]] — 包在模型外面的那一层代码：循环、工具注册、上下文拼装、权限、日志，全部由它负责。

## 关联概念

- [[代理式检索]] — 让 Agent 自己决定检索什么、检索几次、结果够不够，不够就改写再查。
- [[ReAct 范式]] — 把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。
- [[先规划后执行]] — 先用一次调用产出完整计划，再逐步执行，执行中按需重规划。
- [[语言智能体树搜索]] — 把「试一步、估个分、不行退回来」这种下棋式的搜索，套在 Agent 的动作上。
- [[预算控制]] — 为每次运行设定步数、token、时间、金额的上限，超限即降级或中止。

## 常见误判 / 坑

> [!warning] 坑
> 没有显式终止条件，只靠模型「觉得完成了」。这是无限循环与预算爆炸的第一大来源。
