# 多智能体评测

> **L5.P7 · 编排层 / 交付** · 质量面 · 进阶 / 前沿

**Multi-Agent Evaluation**  ·  别名：编排评测、第三层评测

## 一句话

评测编排路径本身：路由对不对、上下文丢没丢、合流时有没有失真。

## 具体是什么样

> 端到端答对了，但中间路由错了两次、上下文丢了三条约束——只看最终答案永远发现不了。

## 看不懂？先看这几个

- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。

## 它解决什么问题

端到端跑通不代表编排正确——多个 Agent 可能靠运气绕过了一个错误路由。

## 它新在哪

这是独立于「单 Agent 质量」的第三个失败面，绝大多数团队只测了前两层。

## 关联概念

- [[路由准确率]] — 请求是否被派给了正确的子 Agent 或处理路径。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。
- [[错误级联]] — 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。
- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。
- [[评测三层级]] — 工具级、单 Agent 级、多 Agent 级各有一套黄金集、评测器与晋级标准，三层都要跑。
- [[黄金集]] — 版本化的评测题集，含标准答案与判定口径，是判断回归的唯一依据。

## 常见误判 / 坑

> [!warning] 坑
> 沿用单 Agent 的评测集。多 Agent 的失败模式（路由、传递、合流）在单轮问答集里根本不会触发。
