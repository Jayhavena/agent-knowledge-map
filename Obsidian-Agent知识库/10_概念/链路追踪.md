# 链路追踪

> **L6 · 系统层 / 观测与成本（环绕全程）** · 运维面 · 核心 / 主流

**Tracing / Observability**  ·  别名：OTel、执行轨迹

## 一句话

逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 它解决什么问题

一次调用涉及多个子 Agent 与工具，「某处出问题了」不是可执行的排查线索。

## 它新在哪

从「日志」升级为「结构化轨迹」：它能被自动评测消费，也能被模型自己读懂并生成诊断。

## 谱系

- **并行** · [[可观测性]]

## 被谁继承

- [[轨迹复盘]] — 对一次失败运行做逐步回放，定位「哪一步开始偏离」，而不是只看最终输出。

## 关联概念

- [[检查点]] — 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。
- [[持久化执行]] — 把每一步执行记录为可重放的事件日志，进程崩溃后从最后一步继续，而不是重头再来。
- [[微服务架构]] — 把系统拆成独立部署、独立演进的小服务，通过明确定义的接口通信。
- [[Agent 外壳]] — 包在模型外面的那一层代码：循环、工具注册、上下文拼装、权限、日志，全部由它负责。
- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。
- [[Agent 运行时]] — 负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。
- [[可观测性]] — 通过日志、指标、追踪三类信号回答「系统内部正在发生什么」。
- [[失败分类法]] — 从真实生产错误反推出的一套互斥的失败类型清单，每类配独立判定口径与评测器。
- [[审计日志]] — 不可篡改地记录「谁在何时让 Agent 做了什么、影响了哪些数据」。
- [[成本归因]] — 把单次请求的成本拆到每一步、每个工具、每个子 Agent，而不是只看总账单。
- [[时延预算]] — 把端到端时延预算拆分到每一层（入口、检索、模型、工具），并分别设上限。
- [[漂移检测]] — 持续采样线上真实流量并打分，与离线基线比对，发现无代码变更下的质量滑坡。
- [[监控告警]] — 为关键指标设定阈值与告警规则，在异常时通知责任人。
- [[评测三层级]] — 工具级、单 Agent 级、多 Agent 级各有一套黄金集、评测器与晋级标准，三层都要跑。
- [[金丝雀发布]] — 把新版本先放给一小部分流量，用真实表现决定是否全量。

## 常见误判 / 坑

> [!warning] 坑
> 只记录「调用成功/失败」。真正有价值的是检索回来的上下文与模型的推理中间态。
