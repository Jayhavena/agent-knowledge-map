# 金丝雀发布

> **L6 · 系统层 / 运行与发布（环绕全程）** · 运维面 · 核心 / 主流

**Canary Release**  ·  别名：灰度、渐进放量

## 一句话

把新版本先放给一小部分流量，用真实表现决定是否全量。

## 它解决什么问题

离线评测无法覆盖真实流量的长尾表达与上游数据变化。

## 它新在哪

在 Agent 场景里它多了一个职责：捕捉「没人改代码」的劣化，如上游索引刷新、模型行为漂移。

## 谱系

- **并行** · [[发布策略]]

## 被谁继承

- [[A／B 实验]] — 把真实流量分成两组，用同一套打分器比较两个版本的实际表现。
- [[发布策略]] — 决定数据、工具、提示词、模型四者的变更如何协同上线，避免半新半旧状态。

## 关联概念

- [[Agent 评测]] — 用可复现的题集与打分器，判断 Agent 在给定任务上「做得对不对」。
- [[回归门禁]] — 每次部署自动跑哨兵集，质量、安全、延迟、成本任一维度越界则阻断发布。
- [[漂移检测]] — 持续采样线上真实流量并打分，与离线基线比对，发现无代码变更下的质量滑坡。
- [[监控告警]] — 为关键指标设定阈值与告警规则，在异常时通知责任人。
- [[部署]] — 把 Agent 服务投入生产环境并持续运行。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 常见误判 / 坑
