# ReAct 范式

> **L4.P3 · 控制层 / 规划** · 定义·机制面 · 核心 / 稳定

**ReAct**  ·  别名：推理-行动交替、thought-action-observation

## 一句话

把推理（Reasoning）与行动（Acting）交织在同一串 token 里，让观察结果实时修正推理。

## 具体是什么样

> 思考「要查退款率」→ 调用指标接口 → 观察结果异常 → 思考「得看是哪个商品」→ 再调用明细接口。

## 看不懂？先看这几个

- [[思维链]] — 让模型先写出中间推理步骤再给结论，显著提升多步推理任务的准确率。

## 它解决什么问题

纯 CoT 会脱离事实空想；纯工具调用则缺少显式的推理依据。

## 它新在哪

不是新东西了，但它是目前 90% Agent 框架的共同祖先。看到任何新范式，第一步就是问它相对 ReAct 改了什么。

## 被谁继承

- [[查询改写]] — 在检索前用模型改写、扩展或假设性作答用户问题，缩小「问法」与「文档写法」的语义鸿沟。
- [[代理式检索]] — 让 Agent 自己决定检索什么、检索几次、结果够不够，不够就改写再查。
- [[Agent 循环]] — 「想一想、动一下、看看结果」反复循环，直到任务做完或该停为止——所有 Agent 的骨架。
- [[先规划后执行]] — 先用一次调用产出完整计划，再逐步执行，执行中按需重规划。
- [[反思]] — 让模型评估自己刚才的输出，找出问题并据此重试或修正。

## 关联概念

- [[原生工具调用]] — 模型直接输出结构化调用指令，而非在自由文本里夹带「我想调用某函数」的意图。
- [[思维链]] — 让模型先写出中间推理步骤再给结论，显著提升多步推理任务的准确率。

## 常见误判 / 坑

> [!warning] 坑
> 认为 ReAct 已经过时。多数「新范式」只是在 ReAct 外面加了规划器或验证器。
