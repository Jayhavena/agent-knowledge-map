# 共享状态

> **L5.P3 · 编排层 / 规划** · 机制·运维面 · 进阶 / 主流

**Shared State / Blackboard**  ·  别名：黑板模式、共享内存

## 一句话

所有 Agent 读写同一份结构化状态（任务板、事实表），而不是靠消息互相传递。

## 具体是什么样

> 所有 Agent 读写同一张任务表：谁领了哪条、状态如何、结论是什么，一目了然。

## 看不懂？先看这几个

- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。

## 它解决什么问题

点对点消息在 Agent 数量增加后组合爆炸，且难以回溯「谁在什么时候改了什么」。

## 它新在哪

黑板架构的老思路，在 LLM 场景重新有效，因为它天然解决了「上下文同步」问题。

## 谱系

- **并行** · [[微服务架构]]
- **组合** · [[多智能体系统]]

## 关联概念

- [[检查点]] — 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。
- [[交接]] — 把任务连同必要的上下文移交给另一个 Agent，并明确谁负责下一步。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[微服务架构]] — 把系统拆成独立部署、独立演进的小服务，通过明确定义的接口通信。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。
- [[错误级联]] — 上游 Agent 的一个小错误在链路中被当作事实继续加工，逐级放大成严重偏差。

## 常见误判 / 坑

> [!warning] 坑
> 无并发控制。两个 Agent 同时写同一字段，后写的静默覆盖先写的，且没人发现。
