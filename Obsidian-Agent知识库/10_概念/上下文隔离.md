# 上下文隔离

> **L5.P2 · 编排层 / 取景** · 机制·成本面 · 进阶 / 主流

**Context Isolation**  ·  别名：子上下文、上下文分区

## 一句话

让子任务在独立的上下文窗口里完成，只把结论回传给主 Agent，中间过程不占用主上下文。

## 具体是什么样

> 子 Agent 读了 50 页文档，只把结论带回主线程，主线程的上下文里不会多出那 50 页。

## 看不懂？先看这几个

- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。

## 它解决什么问题

探索性任务会产生大量无用中间信息，直接挤占主 Agent 的容量与注意力。

## 它新在哪

它不是「并行加速」，而是「降噪」：多 Agent 最被低估的收益在这里，而不是在分工。

## 关联概念

- [[上下文压缩]] — 在长会话或多轮工具调用中，把历史压缩成摘要或摘要+关键原文，控制 token 增长。
- [[多智能体系统]] — 多个具备独立上下文与独立决策能力的 Agent 通过分工与交接共同完成任务。
- [[子智能体]] — 为某个子任务临时派生的独立 Agent，拥有自己的上下文窗口，完成后只回传结果。
- [[上下文传递]] — 在 Agent 之间准确传递「对方需要知道的」：约束、已确认事实、已排除路径、当前进度。

## 常见误判 / 坑

> [!warning] 坑
> 把结论也一起丢掉。隔离的是过程，不是判据——约束、否决理由、未决问题必须回传。
