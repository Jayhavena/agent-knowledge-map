# 发布策略

> **L6 · 系统层 / 运行与发布（环绕全程）** · 运维面 · 进阶 / 主流

**Deployment Strategy**  ·  别名：蓝绿、滚动发布、协同发布

## 一句话

决定数据、工具、提示词、模型四者的变更如何协同上线，避免半新半旧状态。

## 它解决什么问题

数据变更、工具变更、提示词变更分开发布，错配窗口期质量会断崖下跌。

## 它新在哪

Agent 系统有四个可独立变更的层，这是传统软件没有的复杂性。错配窗口是典型的隐性故障源。

## 谱系

- **演进** · [[金丝雀发布]]
- **并行** · [[CI／CD]]

## 被谁继承

- [[金丝雀发布]] — 把新版本先放给一小部分流量，用真实表现决定是否全量。

## 关联概念

- [[提示词版本管理]] — 把提示词当作代码：纳入版本控制、可评审、可回滚、每次变更跑回归评测。
- [[Agent 运行时]] — 负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。
- [[CI／CD]] — 自动化地构建、测试、部署的工程流水线。
- [[回归门禁]] — 每次部署自动跑哨兵集，质量、安全、延迟、成本任一维度越界则阻断发布。
- [[部署]] — 把 Agent 服务投入生产环境并持续运行。

## 常见误判 / 坑

> [!warning] 坑
> 把提示词当配置热更新，绕过了其余三层的协同。一次「小改动」就能造成大范围回归。
