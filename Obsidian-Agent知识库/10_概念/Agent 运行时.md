# Agent 运行时

> **L6 · 系统层 / 运行与发布（环绕全程）** · 运维面 · 核心 / 主流

**Agent Runtime**  ·  别名：托管运行时、执行环境

## 一句话

负责 Agent 的部署、扩缩容、会话隔离、状态持久化与自动埋点的执行底座。

## 具体是什么样

> 不用自己搭容器、排队、状态存储、trace 采集，托管平台把这些都包了，你只写业务逻辑。

## 看不懂？先看这几个

- [[沙箱]] — 给模型生成的代码划一块隔离区：能跑，但碰不到真实文件、真实网络。

## 它解决什么问题

自建运行时需要同时解决沙箱、持久化、可观测与弹性，工作量常超过 Agent 本身。

## 它新在哪

它把「Agent 是一个服务」这件事变成默认假设，而不是每个团队自己拼装。

## 谱系

- **组合** · [[沙箱]]
- **并行** · [[微服务架构]]

## 关联概念

- [[检查点]] — 在每一步之后持久化完整的执行状态，支持恢复、回滚与时间旅行调试。
- [[沙箱]] — 给模型生成的代码划一块隔离区：能跑，但碰不到真实文件、真实网络。
- [[持久化执行]] — 把每一步执行记录为可重放的事件日志，进程崩溃后从最后一步继续，而不是重头再来。
- [[Agent 外壳]] — 包在模型外面的那一层代码：循环、工具注册、上下文拼装、权限、日志，全部由它负责。
- [[发布策略]] — 决定数据、工具、提示词、模型四者的变更如何协同上线，避免半新半旧状态。
- [[部署]] — 把 Agent 服务投入生产环境并持续运行。
- [[链路追踪]] — 逐步记录每次运行的模型调用、工具调用、输入输出、延迟与 token，形成可检索的执行树。

## 常见误判 / 坑

> [!warning] 坑
> 以为托管运行时解决了评测与质量。它只提供管道，定义「什么算好」仍然是你的事。
