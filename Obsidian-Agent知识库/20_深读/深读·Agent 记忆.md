# Agent 记忆

> 深读卡 · 锚点 [[长期记忆]] · 从「存向量」到「会取舍」的完整机制

> [!abstract] 一句话
> 多数团队说「我们有记忆」时，实际只做了检索：把所有对话塞进向量库，需要时捞回来。这不叫记忆，这叫只读检索。真正的记忆系统必须回答一个 RAG 从不回答的问题——什么值得记、什么时候该忘。

## 01 · 内部结构：四段管线，而不是一个库

记忆的价值链条是「写入 → 组织 → 召回 → 巩固」四段。绝大多数实现只做了第三段，所以三个月后必然腐化。

| 环节 | 说明 |
|---|---|
| **① 写入** | 决定什么内容值得进长期记忆、以什么粒度、何时写。这是记忆与 RAG 最本质的分野：RAG 只读，记忆必须回答写入门控。 |
| **② 组织** | 把碎片放进有结构的位置：事实型进语义记忆、经历型进情景记忆、做法型进程序记忆。结构决定召回时的可用性。 |
| **③ 召回** | 按当前任务检索相关记忆，并做冲突消解——同一事实有两个版本时，以谁为准。 |
| **④ 巩固** | 合并、抽象、淘汰。把零散经历压成结论，把过期事实清掉。没有这一段，记忆库会单调膨胀直到召回失效。 |

> 四段里只有第三段能靠「接一个向量库」解决。前三段和后一段都是策略问题，没有现成组件。

## 02 · 六个必须显式回答的问题

这些问题不回答，系统也能跑——只是会在第 90 天开始表现得像失忆或像幻觉。

### 记忆是「用户说了什么」还是「我推断出什么」？

**结论：** 分开存，且推断类必须带置信度。

用户明确说的（「我对花生过敏」）是事实，模型推断的（「这个用户可能偏好简短回答」）是假设。混在一起存，一次错误推断会被当成事实反复引用，且永远无法追溯。

> [!warning] 代价
> 需要两套 schema 与两条召回路径。

### 写入时机：每轮结束都抽事实，还是按需触发？

**结论：** 按需触发，且必须有显式判据。

每轮都抽会记下大量一次性、临时、错误的推断，且越积越难清。合理判据是：用户显式陈述、任务成功结束、或明确的纠正行为。

> [!warning] 代价
> 可能漏记「当时看起来不重要、后来很重要」的信息，需要靠巩固阶段补。

### 冲突时以谁为准：最新覆盖，还是分类处理？

**结论：** 分类。

有些事实是长期的（出生地、过敏史），有些是瞬时的（今天的心情、这次的任务）。用「最新覆盖」一刀切，会让长期事实被一次随口的话永久污染。

> [!warning] 代价
> 要给每个记忆字段标类型与有效期，schema 变复杂。

### 遗忘：不实现、按时间删、还是按价值衰减？

**结论：** 按价值衰减，且保留用户显式声明的例外。

只增不减的记忆库最终变成噪声源，检索成本上升、精度下降。但按时间一刀切会忘掉用户明确告知的稳定偏好，体验倒退比从未记住更糟。

> [!warning] 代价
> 需要访问频率、最后使用时间、显式标记三类元数据。

### 巩固由谁做：离线批处理，还是在线即时？

**结论：** 离线，且结果需要可回溯。

巩固本质是用 LLM 重写记忆，会引入新的幻觉，且层层摘要会丢失细节、放大早期错误。在线做等于把不可控的重写塞进主链路。

> [!warning] 代价
> 记忆会有延迟，刚发生的事不会立刻以「结论」形式出现。

### 记忆与上下文如何分工？

**结论：** 记忆负责「存什么」，上下文负责「这次放什么」。

常见错误是把记忆当作上下文的一部分直接塞进去。记忆库可能很大，每次全量召回会直接挤爆窗口；正确做法是记忆提供候选，上下文工程按预算挑选。

> [!warning] 代价
> 多一层召回-筛选，延迟增加一次检索。

## 03 · 失败模式：记忆的坏是静默的

记忆系统出问题几乎不会报错。它只是慢慢变得更啰嗦、更自信、更不准确。

### 只增不减

三个月后记忆库全是琐碎操作日志，召回全是噪声，模型开始引用无关的旧事。

**修法：** 实现衰减与淘汰；为每类记忆设 TTL。

### 把推断当事实

模型自己猜的属性被存成事实，之后每次都被当作已知条件引用，错误自我强化。

**修法：** 推断类记忆单独标记 + 置信度，低于阈值不进召回。

### 跨会话上下文污染

上一轮任务的中间状态被当成这一轮的已知条件，Agent 从错误的起点开始。

**修法：** 区分「会话级工作记忆」与「跨会话长期记忆」，任务结束即清前者。

### 跨租户召回

共用向量库时，最相似的内容可能属于另一个客户。这类事故是静默的，且极其严重。

**修法：** 写入、索引、缓存、评测集每一层都要隔离，不能只在查询层加 tenant_id。

### 巩固时丢细节

层层摘要后，早期错误被放大，具体数字与条件被抹平。

**修法：** 巩固保留原文指针；摘要只做索引，不做替代。

### 隐私随记忆累积

身份证号、手机号一旦进入记忆库，就同时存在于提示词、轨迹、长期存储三处。

**修法：** 写入前脱敏；删除请求必须能同时清掉派生摘要。

## 04 · 上手路径：先做「读」，再做「写」

推荐顺序与直觉相反：先让系统能可靠召回，再让它学会写。反过来做，你会在一堆垃圾数据上调试召回。

| 阶段 | 动作 | 产出 |
|---|---|---|
| **第 1 步** | 只做会话级工作记忆 + 压缩。当前会话能跨 20 轮不失忆即可。 | 上下文压缩策略 + 预算规则 |
| **第 2 步** | 加只读的长期知识（RAG），验证召回的精确率与召回率。 | 检索基线 + 一组评测题 |
| **第 3 步** | 引入写入，但只接收「用户显式陈述」，且需要人工复核面板。 | 最小写入管线 + 审计视图 |
| **第 4 步** | 加冲突消解与字段类型（长期 / 瞬时）。 | 记忆 schema + 覆盖规则 |
| **第 5 步** | 加衰减、淘汰与巩固（离线批处理）。 | 遗忘策略 + 巩固任务 |

> 多数团队卡在第 3 步：写入一上线，记忆库在两周内被无关信息填满。这恰恰说明第 1、2 步的判据没建好。

## 相关概念

- [[工作记忆]] — 当前会话内可见的上下文窗口，承载本轮任务的临时状态。
- [[记忆写入策略]] — 决定「什么内容值得写进长期记忆、以什么粒度、何时写」的规则或模型。
- [[记忆巩固]] — 把零散记忆合并、抽象成更高层的结论，模拟睡眠中的记忆固化过程。
- [[遗忘机制]] — 按时间衰减、访问频率或置信度主动淘汰低价值记忆。
- [[记忆冲突]] — 当新旧记忆矛盾时（用户搬了家、项目改了名），决定以谁为准。
- [[语义记忆]] — 与时间无关的稳定事实：用户偏好、组织架构、领域概念。
- [[情景记忆]] — 按「时间 + 事件」组织的历史经历：某次发生了什么、结果如何。
- [[程序记忆]] — 把成功的操作序列沉淀为可复用的「怎么做」，下次直接调用而不重新探索。
- [[记忆与 RAG 的边界]] — RAG 是只读的、面向公共知识的检索；记忆是读写双向的、面向个体经历的状态。
